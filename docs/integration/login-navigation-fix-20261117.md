# v0.2.3 登录入口修复

日期：2026-11-17，Asia/Shanghai。基线：01ddc9726faafbacc0f0ba00f2daeb202a86dfcc。

## 问题与修复

无凭据浏览器打开/documents时，实际停留在工作台而非账号登录页。LoginView与/login路由已经存在，但缺少入口守卫；401也只清身份缓存，没有统一处理本地会话与导航。

- 首次路由导航前安装入口守卫，无会话时显示账号密码登录页，记录原站内目标。
- 密码/Token登录成功后返回原页面，保留筛选、分页与hash位置；外链、反斜线、控制字符、未知页面及登录循环回退首页。
- 服务端401清除本地会话并返回登录；403权限不足及503服务不可用不冒充过期凭据强制退出。
- 错误密码由登录表单处理，不清除其他有效会话；旧凭据的延迟响应不影响已经建立的新会话。
- 退出仍沿用服务端撤销接口。没有改账号、角色、认证API、数据库、模型、发布及数据范围规则；前端守卫不替代后端认证。

## 验证

修改前真实无凭据浏览器复现失败：期望/login，实际/documents。修改后内存路由/安全返回/请求凭据策略检查通过，10个相关Vue组件脚本类型检查通过，Vite构建通过。

真实临时HTTP服务、临时SQLite与合成密码账号执行7组浏览器检查通过，页面脚本错误0：匿名深链接、实际密码登录返回、退出撤销、外部返回地址与键盘登录、错误密码保留会话、401失效处理及320/768/1440宽度可操作性。未使用正式用户凭据或正式业务数据。

不把隔离登录检查写成正式业务写入验收，不继承独立QA_PASS。最终镜像、源码SHA与部署后浏览器结果保存于Git忽略的local/login-fix/；实际部署以完成态记录为准。

用户已要求修复并沿用本地部署，按既有选择只更新main与镜像，不新增或移动Git标签。切换前检查活动任务与操作，保留当前容器、镜像和状态；不更改数据库函数或正式runtime。
