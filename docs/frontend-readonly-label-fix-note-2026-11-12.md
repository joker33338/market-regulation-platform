# 「只读」标签成因与文案纠偏说明

> 日期：2026-11-12　范围：前端展示文案纠偏　状态：**说明文档；代码改动已在原前端分支本地提交（见 §7）**
> 本轮未修改后端、未重建镜像、未重启或替换 8180 正式容器、未动数据库与数据卷、未 Push / Merge。

## 1. 现象与结论

配置 Token 后，`/dashboard` 已显示真实统计（4 / 3 / 7 / 7，均带 `REAL`）、「契约就绪」「解析服务：在线」「审核员」，但页头与侧栏底部仍显示 **「v0.2.2 运行期联调通过 · 只读」**。

**结论：Token 已生效，页面并非只读；「只读」是 2026-11-11 联调阶段写死在源码里的历史静态标签，随 v0.2.2 正式镜像一起冻结发布，不随认证状态、接口能力或数据变化。** 它不是功能开关，也不控制任何按钮。

因此「只读」二字描述的是**当时联调只验证了只读接口这一验收范围**，不是当前系统的权限或能力状态。

## 3. 为什么改了源码，8180 上仍显示旧字样

- 8180 正式容器由 FastAPI 同源托管前端 `dist`，产物固化在**镜像内部**（`index-4a01157b.js`）。
- 容器挂载只有运行状态目录、报告目录、模型目录和私有运行配置，**没有挂载 `dist` 卷**，所以宿主机重新构建产物不会同步到运行中的容器。
- 要让 8180 的字样变化，只能重建正式镜像，或直接改动运行容器内的产物文件。两者都违反本轮保护条款（不重建 v0.2.2 镜像、不重启/替换正式容器、不把已验收版本当作开发环境）。
- 故本轮采用任务书要求的**独立开发方式**：源码纠偏 + 本地构建 + 4173 独立预览；8180 保持原样，字样更新交由 Agent C 在正式镜像更新时带入。

## 6. Token 与认证复核（只读）

运行配置中凭证条目 1 条、长度 43；以该条目为 Bearer 凭证访问 `openapi.json`、`documents`、`stats/overview`、`system/health` 均返回 200。该配置是「凭证 → owner」映射，**要填入登录框的是键，不是值**。凭证只在容器内用于本地只读请求，未打印、未写入源码、报告、截图或 Git；浏览器侧只存内存 + `sessionStorage`，关闭标签页即失效。

注意：4173 与 8180 是不同 origin，`sessionStorage` 不共享，打开 4173 预览需重新配置一次 Token。
