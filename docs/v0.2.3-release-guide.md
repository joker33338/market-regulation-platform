# v0.2.3 构建、测试与本地部署指南

唯一源码维护目录为仓库原始主目录。Agent C统一开发、测试、GitHub集成与本地部署；测试结论为自测，不描述为独立QA。v0.2.2正式镜像和旧runtime必须保留用于回滚。

## 构建与身份

使用 scripts/build_release.py 从冻结Git对象构建，必须工作区clean，并已按frontend/package-lock.json准备依赖。脚本不下载模型、不安装运行依赖、不复制私密文件。显式提供已有Node解释器及本机已验证基础镜像；基础镜像需包含requirements.txt与requirements-review.txt对应运行依赖。

正式顺序：功能及集成测试通过、提交开发分支、推送分支、将其集成main、检查远程v0.2.3标签未存在、创建注释标签并推送、核对本地HEAD/main/tag一致后，才以最终SHA构建正式镜像。构建指令示例：

```text
python scripts/build_release.py --revision v0.2.3 --base-image <已验证镜像> --tag market-regulation-workbench:v0.2.3 --node <已有Node解释器>
```

同时保留market-regulation-workbench:sha-<完整SHA>标签。不能用未提交修改构建，不覆盖已有不同revision的正式镜像或Git标签。前后端现已统一在同一Git提交，镜像两个revision标签均应等于最终main SHA。

## 私密配置与持久化

使用compose.local.yaml接入现有数据库网络。LOCAL_APP_IMAGE明确指定冻结镜像，LOCAL_RUNTIME_JSON为已有私密runtime文件，LOCAL_WORKBENCH_ROOT为已有状态根目录，LOCAL_MODELS_ROOT为已有离线模型目录。部署脚本不得把密码、Token、真实文件或模型写入Git。compose.local.yaml不创建数据库、不执行DDL、不自动初始化管理员。

runtime仅支持PARSING_API_TOKENS_JSON、PARSING_RESULT_PG_DSN、MINERU_API_KEY及可选AUTH_ACCOUNTS_FILE、REVIEW_MYSQL_CONFIG_JSON、KNOWLEDGE_WRITE_PG_DSN。保留原Token映射和授权预算。正式market_review创建、正式审核账号/审核写入启用、数据迁移必须另有明确用户授权，部署权限本身不能替代。

PostgreSQL承载业务，MySQL仅承载审核，SQLite保留任务；不移动已有数据来凑唯一源码目录。记录实际外部状态挂载位置但不在公开报告中泄露凭据。切换前备份数据库及状态文件，检查活动任务为0，保留旧容器或可复建配置；禁止删卷。切换后核对.Image、OCI、前端revision、健康、登录页、契约、数据库及实际持久化。

## 能力边界

账号密码与独立身份、ADMIN全权限、USER本人/REVIEWER范围、审核事件、幂等及版本锁、软删除、解析阶段与运行日志、法规/案例只读目录、知识库检索及治理接口均使用真实服务。无ACTIVE返回合法空态。真实法规候选及自动条号定位不等同人工核验，不自动发布，不推测效力/发布日期。

含表格及未确认的人工修订正式导出仍受既有门禁阻断；处罚案例可只读浏览和来源引用，当前无已发布案例数据。不把配置存在当模型或数据库健康，不用云请求做健康探测。宿主GPU全量指标、未知历史阶段回填、公开注册不属于本版本交付范围。

## 测试与完成态报告

单元测试允许合成夹具，但业务联调需真实PostgreSQL、隔离MySQL、本地BGE及原生/OCR、浏览器操作分别给出证据。共享8180写操作不得作为破坏性用例，使用独立PG/测试MySQL与合成账号。明确未覆盖项；不得将自测称独立QA。

正式提交及镜像创建后生成docs/v0.2.3-release-report.md，记录最终完整SHA、镜像ID、容器及测试范围；模板纳入Git，完成态报告作为本地忽略产物及发布附件，避免报告自嵌提交SHA改变其本身。生成后Git仍应clean，所有身份必须通过实际远程ref、标签、容器和镜像查询核对。

## 最终更新入口

scripts/deploy_release.py --image <已核验镜像> --revision <完整SHA> --runtime <获准私密runtime> 默认仅预检查；用户授权后增加--apply。旧scripts/release-docker.ps1的Update/Rollback委托同一工具，支持RuntimeJson参数。工具保留前一容器，健康失败自动恢复；不会初始化账号/数据库或改动业务表。v0.2.2完整回滚还须使用其保留的原runtime/容器，不可把新增字段的runtime强塞给历史入口。

依赖基镜像单独保留为market-regulation-runtime:v0.2.3-py312，实际ID记录在完成态报告，清理测试标签不应删去该依赖。最终候选源码/入口与既有通过测试的业务文件逐项比对，仅补测发布工具及最终部署适配，不机械重跑整套已验收功能。
