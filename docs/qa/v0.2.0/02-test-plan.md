3. Fix 给出实际策略入口、配置和持久化方案；QA 绑定测试适配器，不猜测已经存在的接口。
4. 按 A–J 执行新策略，观察真实业务代码调用；HTTP 使用 MockTransport，禁止真实 HTTP 传输。
5. 在专用 PostgreSQL 验证重试身份、冲突、完整回滚、旧记录保护与来源映射；SQLite 替身不能替代此项。

## 失败注入和资源边界

OCR 输出使用受控文字、置信度与结构，不评估识别准确率。覆盖空文本、异常条号和金额/日期、跨页来源、表格原结构。云端分别模拟超时、429、500、断传及重复恢复；观察提交次数和总调用次数，默认场景上限八次 HTTP 调用、最多一次创建，超过视为失败。实际产品上限可以更严格，但不得无限等待。

每次 v0.2.0 测试进程限定 60 秒；使用 Mock 无需等待真实轮询间隔。配置单独验证缺少地址/授权、禁用云端、预算为零、敏感混合批次以及恢复后仍然保留授权限制。
