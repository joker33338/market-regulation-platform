## 已通过的前置版本

v0.1 本地集成已由 QA 独立验收 PASS：Fix `d2a4c673c596945be14fa4d91a995fd8086e2b31`，PASS 提交 `75c9c1c5e1c263ddc563e8d73ac09ab091789986`。唯一用例 120 PASS，无未解决的已确认 P0/P1。真实云端识别质量、GPU 和生产部署没有随本地验收通过。

## 本版功能 ID

### DUAL-001：本地优先的策略编排

原生 Word/文字 PDF 保留原生路径；简单扫描优先本地 OCR。复杂页可使用本地 Structure；本地结果足够时不上传。按文件汇总逐页质量并记录路由原因。最小版本按文件候选回退，不假设官网与自建 API 的 page_range 完全一致；如需云端逐页优化，先核实官网契约。

建议增加薄策略层组合现有解析器和服务，不重写整个流水线。当前 MinerUService 的模式、Provider、配置一致性和子任务 ID 均有恢复语义，不能简单修改旧任务 mode 来绕过校验。新策略的真实入口及 HTTP 增量由 Fix 明确，本文没有宣称已经存在新路由。

### DUAL-002：质量与法律复核策略

空 OCR、低置信度、复杂布局和条号/金额/日期异常生成可追踪告警。异常条号或日期本身不是修改原文的依据。阈值可配置；文档/页级原因明确。本地失败或缺模型时仍保存已完成页面与错误，不能静默下载模型。经过授权也不代表必须把每个警告交给云端。

### DUAL-003：逐文件外传授权

默认拒绝云端；服务 Key、登录令牌和 MINERU_ENABLED 均不等于文档外传许可。敏感文件没有明确、适用的授权必须拒绝回退。混合批次逐文件判断，不能因一个文件获准就放开全批次。新增许可/审计信息需兼容旧请求；旧客户端没有提供许可时保持本地处理。语料目录及真实资料不用于云端测试。

### DUAL-004：有界兜底、失败保留与成本控制

复用现有超时、上传/下载重试与轮询上限；回退创建结果不确定时不盲目重新 POST。保存远端 ID 后可恢复；单文件重复执行不产生不必要的新计费任务。限制并发、文件大小、候选页数/文件数及总调用预算。官网超时、429 或失败时保留可用本地结果、原始数据和失败原因，不无限循环、不伪装成高质量成功。预算以请求/文件/页数量配置验证，不在测试中产生真实费用。

### DUAL-005：双结果来源、数据一致性与 RAG 兼容

保留引擎/Provider、可取得的版本、路由原因、质量、原结果、页码和来源文件/任务关联。版本无法取得时明确记录缺失原因，不能编造版本或把官方模型档位写成自建 Standard。

注意现有 PostgresResultSink 是不可变结果语义：相同 parse_id 的不同内容会冲突。建议先完成两引擎候选/选择，再对最终结果写一次；中间结果先保存到已有结果结构与原始产物中。若确需双记录，必须明确版本/身份关联，不能先写本地再以同一 ID 覆盖为云端结果，也不能移除冲突检查来获得通过。

复核后继续原有清洗、Chunking、父子关系、Embedding 和入库；未复核、Mock 或表格语义未处理时维持闸门，不扩大泛文档/Excel范围。新增数据库字段/迁移只有在复用现结构确实不足时先提交影响评估。

## 非本版目标

不重建已有客户端、解析器或 RAG；不安装本地 MinerU 模型/GPU；不部署生产；不自动上传真实资料；不新增分布式任务平台；不默认实现尚未确认的 Excel/通用表格 KB 语义。
