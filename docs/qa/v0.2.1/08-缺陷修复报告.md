## 最小实现范围

- 新增 `TrustedTestBatch`：固定服务端 manifest、owner、batch ID，任务创建时持久绑定授权上下文。
- 新增明确 `test` / `TEST_BATCH` 配置，未知环境、未知模式及生产配测试批次直接拒绝。
- 生产默认 `production` / `FILE_SHA`、原语料目录拒绝和逐文件授权语义保持。
- 清单每次重读，校验有效期、撤销、owner、批次及真实内容 SHA。来源合格、敏感性已确认、
  第三方传送权利均须严格为 true；敏感项必须严格为 false，来源证据不能为空。
- HTTP 不能指定 manifest 路径、批次 ID、账本或授权上下文；客户端 false 不能降级服务端敏感事实。
- 合法副本按内容摘要授权，不以路径扩大权限。远端名称使用匿名摘要前缀与扩展名，生产命名不改。
- 全部请求边界沿用既有回调；限流等待后再次检查授权、内容和取消，随后持久记账再发送。
  POST、PUT、轮询、ZIP 和重定向跳转均经过现有请求回调，不改写官方客户端。
- 同批次、同 owner 的总账使用操作系统锁和原子写，跨任务、策略及重启累计，不超过32调用与3个唯一内容。
  相同内容/策略的 POST 有持久占位，未知结果不回滚占位，换任务或输出目录不能盲目重提。
- 清单和账本均拒绝重复 JSON 字段，避免以后值覆盖前值解释权限或预算。

以上改动没有重构路由、Paddle 离线执行、数据库、解析格式或业务栈，也未改变原有审核与候选保留机制。
manifest 是可信服务端配置文件，由部署操作方保护访问权限；不是接受客户端 JSON 后即信任。
支持动态撤销，所以不把整个清单固定摘要当作永不变化的授权。

## 独立小批量入口

`scripts/run_test_batch.py` 默认只 dry-run，最多三个唯一内容、按 auto/remote 顺序单文件执行。
候选生成默认未知，绝不自行把来源、权利或敏感性改成已确认；已知用户批次授权由 QA/操作方落实到清单。
所有输出仅在当前工作树忽略的 local 内；运行任务用批次、owner、模式、内容生成稳定幂等键。
恢复时复用既有任务，不对未完成或结果不确定的任务盲目再发。额度、429 或授权异常保持 BLOCKED。

仅设置这两个参数并不授予网络权限，还须合格清单、服务端身份和原有云端开关与令牌全部有效：

```text
DUAL_OCR_ENVIRONMENT=test
DUAL_OCR_AUTHORIZATION_MODE=TEST_BATCH
```

API 服务端注入可传 `batch_authorizer`；部署配置也可用
`DUAL_OCR_TEST_BATCH_MANIFEST`、`DUAL_OCR_TEST_BATCH_OWNER`、`DUAL_OCR_TEST_BATCH_ID`。
这些配置不开放为 HTTP 输入。凭据继续从原配置取得，不写入清单、账本、报告或命令行。

```text
python -B scripts/run_test_batch.py --manifest <private-manifest> --owner <owner> --batch-id <batch-id> --input <approved-files> --output local/<run>
```

真实执行必须由协调器另行放行后才加 `--execute`。DOCX 缺乏可靠物理页数时仍按既有页预算拒绝，未绕过。
