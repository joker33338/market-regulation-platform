## 配置事实

`ParsingConfig.from_env()` 仅在 `OCR_ENABLE_TABLES=1` 时启用表格；未设置时仍关闭。
直接使用 `DocumentParser()` 或既有双引擎的默认解析工厂会读取该进程配置。
需要表格的独立调用也可以显式传入 `ParsingConfig(enable_tables=True)`。
这些是现有能力，不需要改写表格模型集成，也不应擅自变更全局默认或运行服务。

## QA 已确认的两个问题

1. 双栏原生 PDF 已提取 Native 正文后，进入 Structure 增强分支；增强异常会把整页改成空的失败结果。
   计划仅对确有本页可用 Native 候选的增强失败保留原生正文、版面块和来源，明确标记人工复核与失败原因。
   不改变多栏默认增强策略，不将扫描页隐藏文字层或上一页结果误作当前页兜底，不绕过法律复核。
2. 本地基准脚本未显式传入 `--tables` 时，会以其默认 False 覆盖环境变量的明确启用值。
   计划保留未指定选项时的环境配置，仅在显式 `--tables` 时启用，并记录实际生效的配置。
   不新增关闭选项，不调整图像限额或默认表格开关。

两项已在代码提交 `6216ae5f40727871b369dfc8c54868ac748c4648` 中修复并本地验证，最终结论等待 QA 独立复验。

## 不纳入代码修复的事项

- 六个多栏页与两个复杂扫描页的标签差异仍需核对策略，不能直接强制改为 Native 或 OCR。
- 大图超过资源限额的拒绝属于现有保护，不能单纯提高限额以消除标签差异。
- 原始标注、真实正文及结构标准答案缺失须独立记录，不得编造或修改标签迎合结果。
