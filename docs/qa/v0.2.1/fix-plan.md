## 配置事实

`ParsingConfig.from_env()` 仅在 `OCR_ENABLE_TABLES=1` 时启用表格；未设置时仍关闭。
直接使用 `DocumentParser()` 或既有双引擎的默认解析工厂会读取该进程配置。
需要表格的独立调用也可以显式传入 `ParsingConfig(enable_tables=True)`。
这些是现有能力，不需要改写表格模型集成，也不应擅自变更全局默认或运行服务。

## QA 已确认的两个问题

1. 双栏原生 PDF 已提取 Native 正文后，进入 Structure 增强分支；增强异常会把整页改成空的失败结果。
   计划仅对确有本页可用 Native 候选的增强失败保留原生正文、版面块和来源，明确标记人工复核与失败原因。
   不改变多栏默认增强策略，不将扫描页隐藏文字层或上一页结果误作当前页兜底，不绕过法律复核。
2. 本地基准脚本未显式传入 `--tables` 时，会以其默认 False 覆盖环境变量的明确启用值。
   计划保留未指定选项时的环境配置，仅在显式 `--tables` 时启用，并记录实际生效的配置。
   不新增关闭选项，不调整图像限额或默认表格开关。

两项已在代码提交 `6216ae5f40727871b369dfc8c54868ac748c4648` 中修复并本地验证，最终结论等待 QA 独立复验。

## TEST_BATCH 增量设计（等待 QA 正式交接）

本增量由用户新授权，仅为明确测试环境提供受控批次测试，不改变生产逐文件授权与语料拒绝规则。
当前只读核对，尚未启用真实 API、读取密钥或修改业务实现。

### 受信来源与身份

- 默认保持 `FILE_SHA` 授权及生产环境；只有明确的测试环境和 `TEST_BATCH` 组合可启用批次分支，未知值拒绝。
- 服务端配置载入本地 manifest，不接受 HTTP 提交路径、清单、任意批次 ID 或敏感性降级声明。
- 受信清单按内容 SHA256 索引，包含批次 ID、owner、有效期、撤销状态；逐项确认来源合格、
  第三方传送权利与敏感性已确认。标签或标准答案审核不能代替对外传送权利。
- 本测试模式对敏感或未知分类均拒绝，不新增敏感资料批次授权例外。生产原有逐文件机制不改。
- 服务端在创建任务时持久绑定批次与 owner，恢复任务不能因清单变化改绑其他批次。
  同字节副本以真实内容摘要判断，不以目录位置绕过或扩大授权范围。

### 每次网络边界复验

复用已有 `before_request`：在创建、上传、轮询及下载之前重新检查受信清单、批次绑定、有效期、撤销和文件摘要。
保持既有域名白名单、调用预算、取消和重试机制。请求参数 `sensitive=false` 不能覆盖服务端事实。
批次测试向云端只发送匿名样本名与必要扩展名，生产文件命名逻辑不变。
`auto` 与 `remote` 均保留本地候选完整性及预算检查，不改写既有双引擎或官方客户端。

### 独立小批量入口

先做 dry-run 和 Mock，真实执行另待协调器明确放行。首批最多三个匿名文件，顺序处理；
可按单文件任务保留既有每任务文件预算，不自动调高默认预算。
需要持久 run 级总账约束全部模式与重启恢复，总调用上限不超过既有32次；单文件调用仍最多8次。
429、额度风险或 POST 结果不确定时停止，不通过新任务 ID 盲目重复创建。
本地 manifest、密钥、源路径、真实文件名及结果原文只能保存在忽略目录，不能进入 Git。
