# v0.2.1 当前架构与操作手册

本手册对应 c915 正式业务源码，普通注释整理不改变运行逻辑。[验收快照](../releases/v0.2.1/README.md)是放行依据，历史设计文档仅供追溯。

## 架构和数据流

上传→文件名／格式／限额／SHA校验→任务 SQLite→原生／PaddleOCR／PP-StructureV3→quality→获准的 MinerU 增强→候选选择与复核→document_review 原子保存。

审核后的法规→clean_lines／parse_articles→父子 Chunk→BGE-M3→mr_document_versions、mr_chunks→mr_kb_documents、mr_kb_versions(STAGED)。显式授权 publish 才更新 law_chunks、mr_active_chunk_map、mr_active、mr_release_history。构建、检索和发布有 Schema 身份校验，正式默认 public，QA 显式使用自有 mvp_test_<32hex>。

解析失败不伪造成功；最终缓存复用也校验当前文件大小、像素和页数等安全限制。原件和缓存不静默覆盖，重试保持任务和数据库摘要幂等。云端失败保留本地候选；费用未由供应商返回时不虚构价格。

人工审核桥要求复核人、可用结果和明确法规身份；不把表格摊平成法条。当前 v_review_queue 是 finding 级视图，不等于全部历史待审 documents；没有完整全局审核管理产品闭环。案例预览与法规分开处理，预览不生成真实向量或发布知识库。

## 配置与接口

| 配置 | 实际作用 |
| --- | --- |
| PARSING_API_TOKENS_JSON | 访问码到用户的服务端映射 |
| PARSING_RESULT_PG_DSN | 已有 document_review 保存目标，无自动迁移 |
| PG_DSN | 显式 --postgres 的法规目标连接，不是上传 API 的结果连接 |
| SOURCE_PG_DSN | 外部来源只读连接，实际契约未核验，不自动启用 |
| OCR_MODEL_ROOT、OCR_ENABLE_TABLES | 本地模型位置和表格能力 |
| EMBEDDING_MODEL_PATH、EMBEDDING_DIMENSION | BGE位置及维度，PG要求真实1024维 |
| MINERU_PROVIDER、MINERU_API_KEY | official 官网或 self_hosted；凭据不授予上传权限 |
| DUAL_OCR_ENABLED、DUAL_OCR_CLOUD_ENABLED、DUAL_OCR_GRANTS_FILE | 本地优先、云开关及文件级授权 |

本地 Docker entrypoint 从只读 runtime.json 加载 PARSING_API_TOKENS_JSON、PARSING_RESULT_PG_DSN 和可选 MINERU_API_KEY；默认 local、云关闭、模型在 /models、任务在 /state/parsing，并清理测试连接变量。不得把 TEST DSN 或批次授权混进普通 API 配置。

除主要上传／任务／结果 API 外，还提供 GET /api/parse/info、GET /api/parse/tasks/{task_id}/errors、POST 同任务的 resume/cancel、GET /api/parse/tasks/{task_id}/files/{file_id}/artifact。对外结果隐藏内部路径，用户不能读其他人的任务。

## 部署与恢复

现有活动服务和 state 尚未随代码目录同步移动。固定访问入口仍为 http://127.0.0.1:8180，数据库映射仍为127.0.0.1:15432；MySQL13306和Redis16379继续保留。不要因维护分支同步而运行 compose up 替换服务。

后续有明确切换窗口时，先核对 local/parsing-runtime.json、local/docker-workbench/runtime.json、deployment.json、state 与模型的真实位置，备份活动 SQLite（含WAL的一致性）并确认无运行任务。准备脚本要求干净Git、既有数据库和表、现有模型；存在尚未提交的维护改动时不能声称可直接运行 build/start。

```powershell
# 以下供配置就绪且工作区干净后的操作者使用，本次没有执行。
./scripts/local-workbench.ps1 -Action status
./scripts/local-workbench.ps1 -Action build -Python $Python
./scripts/local-workbench.ps1 -Action start -Python $Python
```

构建使用 deploy/local/Dockerfile，不安装模型。compose.local.yaml 的 /models 和 /private/runtime.json 只读，/state 和日志可写，用户65534、只读根目录、cap_drop ALL、no-new-privileges；app重启策略unless-stopped。默认数据库网不是严格云出口隔离证明，官方客户端另行限制目标域、请求预算和权限。根compose管理三个数据服务；不要 down -v、remove-orphans或prune。

回滚时只更换经核验的应用镜像，保留同一原任务和数据卷；有新旧结果冲突必须保留证据。Windows整机与Docker Desktop登录启动仍需上线前独立验收，容器restart不能代替。云端旧任务403不保证可恢复，不能反复重提文件或清除原POST占位。

## 离线使用与测试

```powershell
# 读取已有归一化结果，避免重复OCR；输出包含原文，只放忽略目录。
& $Python -B scripts/preview_offline_ingestion.py --result $ResultFile --document-type law --output local/preview
# 普通文本法规预览默认不写库。
& $Python -B scripts/ingest_legal_documents.py ingest --input $InputPath
```

含表格的法规须独立处理／复核，不通过预览自动写入法律Chunk。ingest --write需要版本及显式目标；publish/rollback为独立命令，本次没有执行。新环境先查看各脚本 --help，不复制历史机器绝对路径。

当前正式证据为292个唯一方法，285PASS/7SKIP；六项同ID真实PG补测合并291PASS/1环境SKIP。四项部署源文件单测在运行镜像不适用，原ERROR日志保留，宿主PASS复用。真实auto本地成功、自然低质触发、有效双候选和幂等已获独立核验；模型困难样本仍可能低质，必须人工复核，不能写成全量识别准确率100%。

本次注释维护只做无网络轻量回归，不启用真实库DSN、不调用MinerU、不重新建测试批次。原始模型、资料、真值、私有配置和历史工作树都保持原位置。
