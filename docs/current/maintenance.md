# 项目维护入口

## 目录职责
- 唯一长期源码：本仓库根目录；前端在 frontend，业务后端在 qa_core。
- local：本机配置、状态、证据和备份，属于 Git 忽略范围；不可整目录视为临时文件。
- models：模型资产；不归档、不重复下载。
- docs/current：当前有效入口；历史报告需结合受测 SHA 判断适用性。
- 过期文件中的日期归档：保存完整 Git bundle、未提交成果、生成目录与恢复索引，仅本机保管。

## 日常开发
以 main 为已发布基线，按任务创建 codex/功能名称分支。合并完成后检查工作区及独有提交，归档再清理分支。保留版本标签，不重写历史。

## 当前数据依赖
运行状态统一收拢至主目录 local/runtime/state，日志位于其 logs 子目录；实际迁移结果以本机整理报告及容器挂载为准。runtime 配置继续位于主目录 local/release-v023/private；模型绑定主目录 models。数据库数据卷独立保留。

## 发布和回滚
当前运行身份以容器 Image 和 OCI revision 为准；历史 v0.2.3 标签保留原指向，维护更新按用户决定只更新 main 和镜像，不能假定历史标签等于最新 main。
保留 v0.2.2 镜像属于回滚依据保存；本轮按用户决定不执行回滚测试，因此只声明保存回滚资产，不声明回滚已验证。不得通过删除新增审核事件回滚。

## 整理规则
先查容器挂载、配置和脚本引用，再移动文件。Git worktree 使用正式管理命令迁移；禁止直接搬目录导致 Git 关联失效。脏工作区先保存暂存/未暂存补丁和新增文件；归档含敏感内容不得推送。
测试容器先保留日志及配置再移除；数据卷单独审核。构建目录可能含链接，归档只保存链接，不跟随链接删除源依赖。

## 中文注释规则
解释职责、权限、事务、幂等、输入输出、错误恢复和来源保护。简单语句无需逐行复述；历史探针明确适用版本。补注释使用语法树或对应类型检查确认业务结构未改变。

## 本轮进度
详见 tasks/plan.md 与 tasks/todo.md。本轮不开展旧版本回滚测试。已完成全部 Python 静态语法盘点及关键业务边界注释补充；该检查不等于逐行安全审计。运行迁移、分支和镜像清理结果保存在本机日期归档的完成报告中。
