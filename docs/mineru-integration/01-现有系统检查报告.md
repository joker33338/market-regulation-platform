原系统是 CLI，并无 FastAPI、ORM 或任务队列。原有链路：
`scripts/ingest_legal_documents.py::main` → `document_loaders.load_file` →
`service.prepare_document` → cleaner/legal_structure/chunking → embedding → Database。
统一本地解析另由 `DocumentParser.parse` 提供，`bridge.to_legal_document` 要求复核且拒绝表格。
本轮保留原有命令、OCR、Embedding 与知识库发布行为。

本轮可用链路：上传页面 → `mineru_api.create_app` →
`MinerUService.submit/run` → `OfficialMinerUClient` → 安全下载 →
`normalize_artifacts` → `PostgresResultSink.save` → 现有 document_review 表。
任务状态和重试记录使用独立 SQLite；解析正文、Markdown、完整 JSON、页面、文本块、表格存入 PostgreSQL。

只读检查用户提供的本地测试库后发现已存在 document_review.documents/pages/blocks/tables/cells
及审阅视图，因此没有新增、修改或删除数据库表。
法条知识库 public.law_chunks / mr_* 保持不变；解析结果入库不等于法律效力审核或自动发布知识库。

支持上传 PDF、PNG、JPG/JPEG、DOCX；其他格式及泛文档 Chunking 为 GAP-008 待确认范围。
