# v0.2.0 双引擎使用与验收

## 入口和兼容性

使用现有 `create_app`、上传页面和 `/api/parse/*` 接口。新增 `DualEngineRouter` 组合原有 `DocumentParser` 与 `MinerUService`，不替换 OCR、表格解析器、官网客户端或知识库流水线。

设置 `DUAL_OCR_ENABLED=1` 后，API 内部采用新的本地任务模式：Word/文字 PDF 原生提取，扫描件沿用 PaddleOCR/PP-StructureV3。旧客户端只提交 `file_ids` 时仍可用，默认不请求外传。未启用双引擎的旧配置保持原有模式；切换模式前应完成旧队列，恢复检查不会把旧远程任务改成本地任务。

任务可增加 `strategy`（`auto`、`local`、`remote`）、`allow_cloud_fallback` 和 `sensitive`。布尔字段只接受 JSON 布尔值。`local` 永不触发远程；`remote` 仍先保存本地候选，且必须通过服务器授权及预算检查。

## 云端许可

`DUAL_OCR_CLOUD_ENABLED` 默认 `0`。启用后，还必须同时具备官网 Token、请求允许回退，以及服务器许可文件 `DUAL_OCR_GRANTS_FILE` 中与应用用户、文件 SHA256 精确匹配的有效记录。登录 Token、官网 Token 和页面勾选均不能单独授予许可。

许可文件保存在忽略的 `local/` 目录，由管理员维护；结构如下（占位符需替换，不能直接作为真实许可）：

```json
{
  "application-owner": {
    "<input_sha256>": {
      "authorization_id": "<approval-reference>",
      "expires_at": 0,
      "sensitive": false,
      "allow_sensitive": false
    }
  }
}
```

`expires_at` 为未来的 Unix 时间戳。敏感文件需要适用的 `allow_sensitive=true`；请求声明不能清除服务器标记。许可文件在应用启动时读取，更新后需要受控重启；过期时间在每次 HTTP 尝试前检查。语料环境变量所指目录始终禁止外传。单批次逐文件判定。

官网仍调用既有 **v4** API；自建 **4.1 Tasks** 保持独立。没有新建客户端或使用未经核验的旧接口。

## 质量、预算与失败

阈值见 `.env.example`：默认置信度 `0.8`、短页 `12` 字符、异常字符比例 `0.02`。条号重复、跨页、金额和非法日期用于人工复核，不能证明法律正确性，也不会自动改写原文。多栏/网格只是布局提示。原生提取足够时不因普通法律复核提示调用云端。

每文件最多一次回退、8 次 HTTP 尝试；每任务默认最多 32 次请求、2 个云端文件、50 页。上传、轮询、下载及重定向均计入预算，发送前持久化计数；不确定的创建请求不会自动重复 POST。请求之间默认间隔 0.25 秒，复用原有超时和有界上传/下载恢复。

预算按文件和页数预留，失败不退还；不声称精确金额，API 未返回的费用明确为空。DOCX 原生解析无法给出可信物理页数，当前不会绕过页预算强制上传 DOCX。PDF/图片可计数后回退。

远程失败保留本地正文及原因，标记待复核；两端均失败时任务为失败，不能伪装完成。取消只中止后续处理，官网不支持真正撤销已提交任务。

## 结果和数据库

本地 `local-candidate.json` 与云端独立子任务产物保留；最终 `normalized.json` 的 `quality.routing_trace` 包含两端原结果、质量、选择理由、授权标识、哈希、页码、引擎、远端 ID 和使用量。缺少可信版本时记录 `null` 和原因，不以模型档位编造版本。

候选选择完成后才交给已有 `PostgresResultSink`。数据库失败重试使用精确的最终 JSON；不改变 `parse_id`，不关闭冲突保护，不覆盖先前记录。复用 `document_review.documents` 的 `quality`、`source_location`、`original_result`，不需要迁移；原始文件不改写。即使失败，已保存的最终诊断结果仍可通过结果接口读取。

知识库不自动入库。继续通过 `reviewed_legal_document` 和显式复核人，再进入清洗、法条/父子切分、Embedding、暂存发布与检索；Mock 或未处理表格继续被拦截。

## 现有环境与测试

不需要重新创建环境或安装模型。启动脚本支持 `-Python` 指定已有 OCR/BGE Python，`-ApiPackages` 指定已有 API 环境的 `Lib/site-packages`，仅设置当前进程依赖搜索路径。已有默认 `.venv-api` 行为保留；仅有 API 依赖的环境不代表具备本地 OCR 模型。

测试适配器 `tests.dual_engine_adapter:run_scenario` 不使用 `case_id` 分支，仅注入 OCR 输出和官方 HTTP Mock，读取实际任务、结果及数据库。RAG 场景使用原生合成文书、现有 SQLite 演示 Embedding，不代表 BGE-M3 实际识别/检索质量评测。

```powershell
$env:MARKET_REGULATION_DUAL_ENGINE_TEST_ADAPTER='tests.dual_engine_adapter:run_scenario'
python -B tests/run_v02_acceptance.py --source .
python -B -m unittest tests.test_dual_engine_policy -v
python -B tests/round01_isolated_postgres.py --source . --output local/v02-postgres --include-v02
```

最后一条复用本地已有镜像，创建无宿主端口的内部测试网络和新数据库，执行后停止数据库、保留数据与忽略的资源记录。不使用业务库，不拉镜像，不迁移生产 Schema。完整验收结果和提交见 Fix 交接报告；云端真实批量质量、GPU、生产部署另行验收。
