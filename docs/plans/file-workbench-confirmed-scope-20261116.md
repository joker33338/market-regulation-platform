## 2. 用户已确认的设计

| 编号 | 结论 | 实现要求 |
|---|---|---|
| Q1 | 统一文件处理工作台 | 按处理中、待审核、待发布、已发布、需处理查看；在文档上下文内完成下一步，法规库和处罚案例库提供最终查阅。 |
| Q2 | 自动推进机械步骤 | 上传完成自动提交解析；人工审核通过后自动预检和候选构建；准备完成后待发布。质量、归类、冲突等问题进入人工处理。 |
| Q3 | 批量文件分别推进 | 成功结果保留，失败文件单独显示原因，只重试失败项；集中确认准备好的候选。 |
| Q4 | 辅助归类 | 上传支持整批指定法规或案例，也可自动提出归类建议；类型不明确或混合时由用户确认，不能猜测归库。 |
| Q5 | 异常优先审核 | 优先展示缺页、乱码、表格问题和关键信息问题；支持原件/结果对照、修订、下一份；批量审核须明确选择并确认。 |
| Q6 | 明确发布范围 | 发布前显示实际选中文档、目标库、准备完成数量及阻断项；新增资料保留原有已发布内容，重复和更新不得静默覆盖。发布后直接查看本次结果。 |
| Q7 | 汇编拆分建议 | 一份原文件中的多法规/多案例分别形成建议条目和来源范围，经用户确认后分别入库；保留原件与页码/位置映射，识别不可靠时待处理。 |
| Q8 | 文件与目录上传 | 支持选择多个文件、文件夹及子文件夹，保留目录分组；上传前呈现文件数、重复项、不支持项；按分组和异常查看进度。 |
| Q9 | 统一搜索与组合筛选 | 搜索文件名、资料标题、文号或案号；常用筛选为资料类别、业务状态、上传批次和上传时间，显示已应用条件，支持清空与保存常用筛选。内部标识放入详情。 |
| Q10 | 连续查看 | 列表旁直接预览原件、识别正文、业务信息和处理进度，支持上一份/下一份；关闭和返回保留筛选、页码与位置。 |
| Q11 | 跨页选择 | 翻页保留选中；区分当前页选择与全部筛选结果选择。执行前核对真实范围及数量，筛选改变须重新确认范围。 |
| 补充 | 整批数量不设固定上限 | 后台自动分批、排队和受控并发，不要求用户按每次 20 份手动拆批。保留单文件大小及现有授权/资源保护。 |

## 3. 自动处理与人工确认

主流程：上传完成 → 自动解析 → 归类/拆分确认（需要时）→ 人工审核 → 自动预检与构建 → 待发布 → 显式确认发布 → 对应库查询。

- 上传尚未完成的文件不显示为已提交任务；关闭浏览器不能被描述成会继续上传尚未传完的本地文件。
- 已成功提交的后台任务独立于页面生命周期运行；刷新、重新登录后按真实持久化状态恢复查看。
- 工作台显示上传、解析、审核、构建、发布各阶段，不用解析 completed 冒充审核或入库完成。
- 审核通过不等于发布；模型建议不等于审核。审批撤销、原件变化、修订变化和版本冲突需要重新检查。
- 入库构建复用已审核解析结果，进行清洗、结构化、切分及真实向量构建，不重复触发 OCR/MinerU。
- OCR、MinerU 沿用当前真实引擎路由和授权，不因本轮自动化默认开启外部云调用。
- 原件、原始 OCR、修订、人工操作及发布历史分别保留；修改后的最终审核正文必须有明确导出/绑定协议，不能静默入库旧正文。
- 现有上传/审核记录按实际状态接入；缺少证据时显示未开始或待核对，不猜测完成、不自动重跑历史资料。

## 4. 已查明的源码缺口

- DocumentsView.vue 将文件名/格式/解析状态搜索和高级日期排序分开；主要表列包含 SHA256 和任务 ID。
- 文件批量选择目前只保留当前页，翻页、查询、刷新后清空。
- 详情的解析历史空态缺少开始解析入口；尚未解析文件在列表使用“重新解析”文案。
- IngestionView.vue 要求用户填写目标 kb_version、documents JSON、parse_id 和 expected_review_version。
- qa_core/api/ingestion.py 每个请求最多 20 份，这是现有传输/处理边界，不应成为整批业务数量限制。
- storage/library_projection.py 当前正式候选投影固定为 law；案例链路需要正确的独立类型处理，不能只改标签。
- 当前入库拒绝未明确导出的人工修订；需实现可追溯的最终正文承接，不能解除阻断后直接用旧 OCR。

上述为源码核查，不能单凭此表认定线上修复或完整引擎质量已验证。

## 5. 实施顺序

1. 定义批次、文件、业务条目、处理阶段、异常原因、可用动作和来源映射的契约；补齐真实状态聚合及搜索/筛选需求。
2. 实现可恢复的后台批次调度及幂等、失败项重试，复用现有解析任务与审核台账。持久化方案先核对现有 Schema；如需增量变更先列明，不能在页面请求或测试启动时自动修改正式库。
3. 打通法规与案例适配、确认后的拆分范围、最终审核正文与候选构建；保留全部来源、权限和发布门禁。
4. 实现统一工作台、上传预览/目录分组、真实进度、异常处理和连贯的审核/入库入口。
5. 完成文件库统一搜索、组合筛选、常用条件、连续预览、位置恢复及跨页选择。全部匹配选择由服务端复核并固定操作范围，不在浏览器一次拉取全部文件冒充跨页能力。
6. 更新 Pydantic/OpenAPI/TypeScript 契约、用户说明和测试证据；使用候选验证后再按当次授权安排运行更新。

## 6. 验收标准

- 用户只选择文件、核对业务信息、审核和发布，不需要输入内部技术字段。
- 上传后能持续看见真实处理阶段，未解析时有清晰入口；审核通过后有下一步和最终去向。
- 超过单次请求边界的整批文件能自动分批，成功、失败、重试统计不重复，不静默截断文件。
- 刷新和关闭页面不影响已提交后台任务；部分上传、网络中断、状态不确定有独立语义。
- 法规、案例进入各自目标库；类型、来源范围、修订和原文绑定经过确认；不可靠拆分和表格处理继续阻断受影响条目。
- 异常文件不阻塞无关文件的解析和审核；不完整的同一业务条目不能因局部成功而发布。
- 审核/发布权限由后端逐请求核验；跨页/全匹配批量操作不能扩大数据范围。冲突、撤销、重复点击及超时不会导致重复写入或误报成功。
- 发布前列明准确范围并再次检查真实审批和来源；发布后库中可查到对应数据，原有内容不被意外覆盖。
- 搜索/筛选按服务端完整结果分页，修改条件回到首页；可清空、保存与恢复，预览返回保留位置。
- 多选跨页准确，当前页与全部匹配范围明确，筛选变更不会沿用错误操作范围。
- 浏览器覆盖 320/768/1024/1440 宽度及键盘操作，检查加载、空态、无权限、失败、重试、成功和恢复状态。
- 单元、接口、真实隔离数据库、实际浏览器与引擎测试分别记录；不沿用历史 PASS 代替新增验证，不以模拟响应证明真实业务上线。
