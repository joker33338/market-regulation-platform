# v0.2.4 已确认范围与验收方案

日期：2026-11-16。依据：本次 grill-me 访谈中用户逐轮接受的 Q1—Q18，以及后续关于 OCR 分流和测试证据的澄清。

本文是已确认的设计方向，不是实现、测试或部署完成声明，也不自动授予业务开发、真实 OCR、数据库写入或发布权限。长期规则见 [AGENTS.md](../../AGENTS.md)。

## 1. 首期目标与范围

首期形成法规、处罚案例的可追溯待审核闭环，并在质量不降低的前提下减少每份文档从上传到审核完成的人工操作时间。发布仍须人工审核和显式执行。

| 范围 | 首期承诺 | 后续或条件事项 |
|---|---|---|
| law / penalty_case | 解析、类别确认、业务切分、字段候选、质量评估、人工修订与待审核保存 | 必填字段和业务阈值须在基线后冻结 |
| enforcement_doc / other / unknown | 识别、原文及候选保留、分流与人工确认 | 专用字段抽取和完整业务流程不列为首期必交付 |
| 混合文件 | 原始父身份不变，人工确认业务边界 | 不承诺自动完成混合文档拆分；子范围继承权限和来源 |
| 复杂表格 | 原件查看、问题定位、候选保留及已具备能力的验证 | 缺少可靠修订/导出协议的内容阻断相关发布，列为未完成 |
| 历史文档 | 用户选定单份或批次后重新处理为新候选 | 不做全库自动重分类、重切分和重建索引 |

旧 case 与目标 penalty_case 须明确兼容映射；首期范围不能直接写入旧数据库约束。详细长期技术方向保留在 [原方案归档](../history/AGENTS-before-20261116-revision.md) 第 3—7 节；其中更大的目标不扩大本期范围。

| Q8 六维质量 | 每项注明适用性、是否必需、是否阻断和依据；六维有记录，不要求所有指标都能自动判断正确；必需指标不可用时明确补证路径 |
| Q9 人工边界 | 人工确认或修订可解决业务疑问并触发重评估；不得豁免越权、哈希不一致、版本错配等完整性问题 |
| Q10 局部失败 | 保存成功页和候选，支持失败页重试；必要内容完整性确认前阻断整份业务文档发布，不自动将成功页伪装为完整文档 |
| Q11 重解析 | 新解析形成新候选；旧人工修订仅作对照，人工核对后应用，新版本重新审核；首期不承诺跨解析版本自动迁移修订 |
| Q12 样本标注 | 用户指定具备业务判断能力的人员确认标注并裁决争议；Agent 负责整理和统计，不以自身生成答案充当验收标准 |

| Q14 阈值冻结 | 基线与调试完成后确认目标并冻结，再执行独立验收；关键安全/完整性错误出现即不通过，不把有限样本零发现称为零风险 |
| Q15 字段分级 | 两类业务分别定义必填、条件必填和可选字段；待审核保存允许不完整，审核与发布分别检查适用必需项 |
| Q16 表格限制 | 无可靠修订协议时允许停留复核；计入未完成和人工成本，转人工不算处理完成；若导致整体目标不达标，须补能力或重新协商范围 |
| Q17 历史稳定 | 新流程先用于新文件；明确选择历史文件后才重处理，原发布版保留到新版本显式替换；实质错误走撤回/纠正流程 |
| Q18 渐进启用 | 隔离端到端验收后，获准有限试用并由人工确认后保存；达标且获准后启用合格文件自动待审核保存；始终保留审核与发布门禁 |

Q10 中空白页或无关附件的排除须由人工按明确规则确认，保留原件、范围及理由。Q18 停用自动流程后，已保存候选仍须可处理，既有接收流程保持可用。

## 3. OCR 专项优先级与证据边界

历史核查发现页级选择代码；用户当前反馈智能分流尚未实现。当前需查明缺实现、未启用、引擎不可用、实际链路未调用、版本不一致或展示错误中的具体原因，不能用旧快照代替本次判断。

在既有版本门禁和当次授权范围内，按以下顺序推进：

1. 核对源码、配置、运行版本和完整调用链；若运行配置不可读取则保留证据缺口。
2. 使用获准真实样本测当前流程基线，记录每页实际引擎、原始产物、问题、耗时和人工成本。
3. 在调试集做必要且获准的指定引擎对比，为规则提供依据；不得通过试验集调参污染独立验收。
4. 复用既有实现修复最小路由与展示问题，记录特征、决策理由、计划和实际引擎、失败及有限回退。
5. 用独立样本对比新旧流程的实际选择、最终解析质量、系统耗时和人工修订成本。
6. 上游证据充分后再验收分类、切分、审核的整体效果。下游可用固定产物做隔离开发和测试，但结论不外推到上游。

当前流程测试是基线；人工指定引擎的效果不是自动路由效果；Mock 只能验证相应逻辑。只有实现后的真实端到端测试才能支持智能分流的效果结论。运行镜像未更新时，明确源码测试与当前服务状态的区别。

上述顺序允许在一次明确授权的任务中连续完成，不要求用户逐步重复批准；新增依赖、云调用、正式数据写入、部署等仍按实际范围授权。

## 4. 质量、审核与状态设计要求

- 六维覆盖 OCR、版面、切分、分类、元数据和溯源；每个指标区分实测、推导、不可用及非适用，不混合 OCR 置信度、BGE 相似度和切分覆盖率形成统一分数。
- passed 只表示适用必需检查通过；needs_review 表示有产物待核对；failed 表示关键条件不满足；unavailable 表示证据或能力缺失。质量状态不替代审核状态或发布权限。
- 优先处理安全、来源和解析失败，再处理分类冲突、元数据缺失；保留全部原因，后一步不能覆盖失败。
- 分类冲突可展示候选预览，但人工确认前不建立已经确定类别的业务记录。
- 向量失败保留解析/切分候选与独立重试状态，不伪造 embedding。候选持久化与索引构建分阶段，事务、幂等和恢复路径分别验证。
- 字段候选必须携带原文定位，区分机关认定和当事人陈述。是否必填按业务用途和适用性确定，不为填满表单编造内容。
- 首期需完成原件对照、问题定位、分类确认、字段修订及审核提交；技术指标按问题呈现，不要求审核人员逐项阅读技术报告。

## 5. 验收安排与开工前置条件

以下事项尚待落实，不得由 Agent 编造已完成状态或自行设定业务答案：

| 事项 | 责任与完成要求 |
|---|---|
| 版本前置状态 | Agent 核对 v0.2.3 发布、部署与试用证据；不能仅根据分支名或报告标题判断完成 |
| 样本及使用授权 | 用户确定可用语料及范围；优先复用既有数据，外传授权单独核对 |
| 标注与争议裁决 | 用户指定业务人员；Agent 整理候选标注、异常与统计，不自行充当最终答案 |
| 样本规模/分布 | 根据实际法规、案例、易混淆类型及复杂度确定；按来源文件分调试集和独立验收集 |
| 业务字段清单 | 业务人员确认必填/条件必填/可选及各阶段门禁，Agent 提供基于现有契约的草案 |
| 基线与目标 | 获准后测人工操作、系统等待、完成率、错误类型；再确认省时目标、完成率和各类错误上限 |
| 资源与延迟预算 | 核对机器及实际负载后提出并确认，不由两句模型冒烟推断长文或并发性能 |
| 最终验收 | 固定规则、版本、阈值和独立样本；报告分母、样本数、机器、运行方式、失败及未覆盖项 |

这些前置条件按依赖阶段落实：不妨碍已授权的只读核查、文档整理和隔离机制测试；未经必要授权不得执行依赖真实语料、生产状态或外传的工作。
